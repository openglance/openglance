# Hosted `/open` and `/share` links

English | [简体中文](hosted-links.zh-CN.md)

OpenGlance documents remain in local Git repositories. The public HTTPS links generated by OpenGlance use a
small Mango Future hosted handoff service at `gitleaf.mangofuture.com` so browsers and chat clients can
launch the installed desktop app.

The service is a protocol handoff, not a hosted repository, knowledge base, or context service. It does
not clone a repository, read a document body, grant GitHub access, or make a private repository public.

OpenGlance itself generates canonical `openglance://` links. During the installed-client migration, the
hosted page launches the equivalent `git-leaf://` compatibility link because it is the one protocol
registered by both Git Leaf 1.x and OpenGlance. This does not change the visible product
name or the canonical link format copied by OpenGlance.

## `/open`

An ordinary document link can transmit these URL fields:

| Field | Meaning |
| --- | --- |
| `repo` | Lowercase GitHub `owner/repository` identity |
| `path` | Repository-relative `.md` or `.mdx` path |
| `worktree` | Optional 16-character local worktree ID for a same-machine exact link |

The worktree ID is derived from a canonical local path but does not include that absolute path. It is not
portable to another machine. A link without repository fields only launches or focuses OpenGlance.

Without `worktree`, the app opens the document in the matching repository's primary checkout, even if
the last session used a linked worktree. With `worktree`, it opens only that exact available local
worktree and reports an error if it is missing. A missing document is reported in the selected checkout;
the app does not search other worktrees or synchronize the repository as part of `/open`.

## `/share`

A version-1 shared document link can transmit:

| Field | Meaning |
| --- | --- |
| `v` | Protocol version, currently `1` |
| `repo` | Lowercase GitHub `owner/repository` identity |
| `path` | Repository-relative `.md` or `.mdx` path |
| `rev` | Full Git commit that must be present on `origin/main` |
| `title` | Optional document title, limited to 100 characters, for link previews |

OpenGlance no longer sends document snippets or `ai_snippet`. The hosted endpoint accepts a bounded legacy
`snippet` query only so old links keep working.

Anyone who receives a link can see its repository identity, path, revision, and optional title. Avoid
sensitive information in a path or title. The link does not include repository content, local absolute
paths, Git credentials, access tokens, diffs, clipboard content, or the sender's Git identity.

## Handoff state

For each browser handoff the service creates a random one-time ID and keeps only a small in-memory state
such as pending, received, opened, cancelled, or failed. It expires after ten minutes and is not a
persistent repository or document record.

The browser page polls that state so it can distinguish a successful app open from a browser merely
losing focus. The desktop app writes its own handoff diagnostics to the local `deep-link.log` under
Electron user data.

## Normal HTTPS metadata

As with any web request, Mango Future's hosting stack can receive the request timestamp, source IP,
user-agent string, requested URL (including the fields above), and HTTP headers supplied by the browser.
Reverse-proxy access logs are retained for at most seven days under the analytics and privacy contract.

The handoff response uses `Cache-Control: no-store`, a restrictive Content Security Policy, and
`Referrer-Policy: no-referrer`.

## What happens after handoff

The installed app matches `repo` against repositories the user has already opened. If necessary, it asks
the user to choose a local directory and verifies the GitHub origin. For a shared link, the app uses that
repository's existing local Git credentials to fetch `origin/main` and verify `rev`.

Mango Future's handoff service does not perform that Git fetch and receives no Git credentials. A shared
link grants no access that the recipient does not already have.

## Downloads are separate

`/open` and `/share` do not provide installers. The normal
[download page](https://gitleaf.mangofuture.com/download) never triggers a desktop protocol and shows only
explicit public release artifacts.
